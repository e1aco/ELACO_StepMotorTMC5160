# 过温优化 — 阶段 1：子系统拆分

> 2026-07-31 · deep 档 · 待解决项 2/4「电机/芯片发热排查」

## 问题定义

TMC5160 芯片运行中温度 ≥143°C（DRV_STATUS bit25/26 置位，CAN 状态标志 bit2 持续为 1）。
软件侧通过寄存器配置降低发热，验收目标：**消除 bit2（芯片 <143°C）**。

## 根因链（软件可干预部分）

```
IRUN/IHOLD 电流设置偏高  →  MOSFET/线圈 I²R 损耗大  →  芯片温升
TPOWERDOWN 未显式配置    →  静止降流时序不可控
StealthChop 静止电流     →  待机时 PWM 开关损耗
CoolStep 未启用          →  轻载时无法自动降流 ~75%
斩波频率/电流斜率        →  开关损耗次级因素
```

## 子系统划分

| 子系统 | 范围 | 说明 |
|--------|------|------|
| **A. 电流参数子系统** | IHOLD_IRUN / GLOBAL_SCALER | 校正 IRUN=10 的电流量级（真实 ≈1.56A RMS @0.05Ω，注释误写 203mA），按电机额定 1.5A 调整 |
| **B. 静止降流子系统** | TPOWERDOWN / IHOLDDELAY | 显式配置静止→IHOLD 时序，避免待机持续 IRUN 电流 |
| **C. CoolStep 节能子系统** | COOLCONF / TCOOLTHRS | 轻载自动降流（官方节能 75%），保守配置 |
| **D. 斩波/驱动子系统** | CHOPCONF / PWMCONF / DRV_CONF | 开关损耗微调 + 过温阈值确认（DRV_CONF.OTSELECT=150°C 已是上限，芯片 143°C 报警来自温度本身） |
| **E. 状态监控子系统** | DRV_STATUS 读取 / CAN bit2 | 验证手段：确认过温标志来源与温度余量评估（不改逻辑，只用于验证） |

## 依赖关系

```
A（基础电流） ← B（静止降流） ← C（CoolStep 在 A 的电流范围内工作）
D ← A/B/C 全部（斩波配置影响电流波形）
E（验证） 依赖 A~D 全部完成
```

> 3 个子系统含互锁依赖，但改动集中在 `ela_tmc5160_init()` 一个函数（≤5 处寄存器写入），
> 无需并行子 Agent —— 顺序执行即可，每步可独立验证（见 milestones.md）。
